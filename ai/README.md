## 只拿到仓库地址时，从哪里开始

1. 先读本页和 `llms.txt`，确定用户是在理解方法、提出方向、比较作品，还是整理经验。
2. 按下表读取对应正文。概念索引用于找路，具体判断仍应回到文章和用户材料。
3. 输出时说明实际读取了哪些篇目，区分文章观点、用户提供的事实与本次推断。未读取的篇目不算已掌握的依据。

| 用户的任务 | 建议先读 | 需要补充的材料 |
| --- | --- | --- |
| 理解全套方法 | 第 01—03、12 篇 | 想解决的创作问题 |
| 说清“感觉不对” | 第 04、08 篇 | 实际作品、展示尺寸和目标 |
| 整理参考与创作方向 | 第 05、06 篇 | 任务、受众、参考职责与约束 |

逐篇直链在 [精简索引](../llms.txt)，篇目、章节标题和内容校验值在 [机器可读索引](index.json)。章节较长时，先定位相关小节，再读取前后文；无法读完时，明确本次覆盖范围。

## 怎样取得正文

- **能够读取 GitHub 文件**：读取 `content/` 中的独立 Markdown。`llms.txt` 同时列出无需解析 GitHub 页面界面的 Raw 直链。
- **能够读取公开网址**：从 `https://leenlbma.github.io/aesthetic-engineering/llms.txt` 开始。
- **适合一次性读取全文**：使用 `llms-full.txt`。它包含本阅读入口、概念索引、任务示例、12 篇全文和参考资料，不是摘要。
- **不能访问链接**：请用户粘贴对应文章，或上传仓库中的 Markdown；不要根据文件名补写文章观点。

部分工具不会自动寻找 `llms.txt`，需要用户明确提供地址。完整文本包可能超过某些工具单次读取的长度，按任务读取通常更省上下文。

## 阅读时应保留的区别

- 六层结构是职责划分，不要求实现六个模型，也不是经过统一验证的行业标准。
- 概念公式、比例与“审美梯度”用于说明关系。数学或研究结论需核对 [参考资料](../content/参考资料.md) 中列出的原始来源与支持范围。
- 观察、解释与判断分开写。没有看到图片或视频，就不能声称看见了其中的细节；静态帧也不能证明整段视频的节奏与一致性。
- 个人喜欢、任务适配与业务效果分别需要依据。没有相应数据时，不从视觉评价推断点击率、转化率或销售效果。
- 原始选择、偏好假设、当前约定分开保存。一次临时选择不自动成为长期偏好；当前明确要求可以改变历史默认。

## 怎样引用

引用作者 **LeenMa**、篇号、标题和具体小节，并给出原文链接。例如：第八篇《Aesthetic Critic：AI 如何帮你做判断？》第二节“先让 AI 指出证据，再听它解释”。任务示例中的新模板请标为“依据本文方法整理”，不要当成正文原话或已验证结果。

回答仓库事实时，可以说明“读取了哪些文件、基于哪个提交”。仓库 `main` 会更新；需要复现时，使用对应提交的文件链接。`ai/index.json` 的 SHA-256 校验值用于识别具体内容，不代表内容质量评分。

```text
再按我的任务选择相关正文：［填写任务］。
先说明你实际读取的篇目和还缺少的输入，再应用方法。
引用篇号与小节；把实际观察、推断和建议分开。
不要把文章示意案例当成我的作品事实。
```

这组入口与示例是阅读辅助，不是对模型理解、评审可靠性或创作效果的保证。具体工作方式见 [三个任务示例](tasks.md)。
